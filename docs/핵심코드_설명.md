# 핵심 코드와 기준값 정리

이 문서는 코드에서 **실제로 판정을 결정하는 부분**만 뽑아 설명합니다.
숫자는 전부 `data/reference/season_reference.json` 한 곳에 있고, 코드에는 숫자를 박아두지 않았습니다.
(발표 때 "기준을 바꾸려면 JSON 한 줄만 고친다"고 말할 수 있게 한 구조입니다.)

처리 순서는 이렇습니다.

```
사진 → ① 흰 종이 찾기 → ② 조명 보정 → ③ 얼굴 부위별 색 추출
     → ④ 촬영 조건 점검 → ⑤ 웜/쿨 판정 → ⑥ 4계절 배분 → ⑦ 신뢰도
```

## ① 흰 종이 찾기 — `backend/vision/paper.py`

사진 안에서 "종이처럼 생긴 덩어리"를 찾습니다. 밝기 하한을 8단계로 올려가며 후보를 모으고,
**조건을 만족하는 첫 후보에서 멈추지 않고 전부 점수를 매겨** 가장 좋은 것을 고릅니다.

```python
score = clean * bright * extent * sat_ok * size_ok * max(0.0, border_ok)
```

| 항목 | 뜻 | 이유 |
|---|---|---|
| `clean` | 포화(250 이상) 안 된 화소 비율 | 하얗게 날아간 덩어리는 기준색으로 못 씀 |
| `bright` | 평균 밝기 ÷ 255 | 종이는 밝다 |
| `extent` | 덩어리 넓이 ÷ 외접 사각형 넓이 | 종이는 네모나다 |
| `sat_ok` | 1 − 평균 채도 ÷ 60 | 종이는 색이 없다 |
| `size_ok` | 사진의 3% 미만이면 감점, 15% 초과도 감점 | 손에 든 종이는 보통 2~15% |
| `border_ok` | 사진 테두리에 닿는 면마다 25% 감점 | 벽·창문은 테두리에 닿는다 |

> 처음엔 첫 후보에서 멈췄는데, 브라우저가 캡처한 JPEG 은 원본과 화소가 미세하게 달라서
> **그 정도 차이로 종이 대신 벽이 잡혔습니다.** 전부 점수를 매기는 방식으로 바꿔 해결했습니다.

찾은 종이에서 기준색을 뽑을 때는 세 종류를 뺍니다.

```python
keep = (px < TRIM["saturated"]).all(axis=1)      # ① 포화(250↑) 제외
lo = np.percentile(lum, TRIM["shadow_percentile"])   # ② 어두운 쪽 25% (그림자·접힌 자국)
hi = np.percentile(lum, TRIM["specular_percentile"]) # ③ 밝은 쪽 5% (반사광)
sel = px[(lum >= lo) & (lum <= hi)]
return sel.mean(axis=0), info
```

| 기준값 | 값 | 근거 |
|---|---|---|
| `saturated` | 250 | 이 위로는 원래 색을 복원할 수 없음 |
| `shadow_percentile` | 25 | 그림자는 조명색이 아니라 그늘색 |
| `specular_percentile` | 95 | 249짜리 반사도 색을 왜곡함 |
| `min_clean_ratio` | 0.25 | 반사가 있어도 1/4 이 멀쩡하면 기준색을 뽑을 수 있음 |

**사람이 종이에서 깨끗한 부분을 손으로 골라 찍던 것을 자동으로 하는 것**과 같습니다.

## ② 조명 보정 (화이트밸런스) — `backend/vision/lighting.py`

```python
def estimate_gains(img, white_box, target=255.0):
    avg = crop(img, white_box).astype(np.float32).mean(axis=(0, 1))  # [B, G, R] 평균
    avg[avg == 0] = 1.0
    return target / avg
```

흰 종이가 목표값이 되도록 B·G·R 각각에 배율을 곱합니다 (von Kries / White Patch 방식).
종이가 실제로 흰색이라는 사실을 이용해 **카메라와 조명의 색 치우침을 되돌리는** 것입니다.

| 기준값 | 값 | 근거 |
|---|---|---|
| `white_balance.target` | **235** | 255로 맞추면 종이보다 밝은 부분이 잘려나감. 235면 여유가 생김 |

> 화이트밸런스는 선택이 아니라 필수입니다. 없이 판정하면 **같은 사람도 9.7° 흔들립니다.**

## ③ 얼굴 부위별 색 추출 — `backend/vision/face_color.py`

MediaPipe FaceMesh 의 478개 점으로 볼·이마·눈동자·머리카락 영역을 잡고,
영역 안 픽셀에서 **이상한 것을 버린 뒤 평균**을 냅니다 (절사평균).

```python
def robust_mean_lab(pixels_bgr, trim_low=None, trim_high=None, saturated=None):
    px = pixels_bgr[(pixels_bgr < saturated).all(axis=1)]   # ① 반사광 제거
    lab = bgr_pixels_to_lab(px)
    lo, hi = np.percentile(lab[:, 0], [trim_low, trim_high])
    keep = lab[(lab[:, 0] >= lo) & (lab[:, 0] <= hi)]       # ② 밝기 상·하위 제거
    return keep.mean(axis=0), len(keep)
```

| 기준값 | 값 | 무엇을 막으려고 |
|---|---|---|
| `trim_low` / `trim_high` | 10 / 90 | 그림자·점·잔머리(아래) / 번들거림(위) |
| `saturated` | 250 | 하얗게 날아간 반사광 |
| `min_pixels` | 30 | 픽셀이 적으면 그 부위는 안 씀 |
| `forehead_max_de` | ΔE 12 | 이마가 볼과 너무 다르면 앞머리·그림자로 보고 제외 |
| `cheek_pair_warn_de` | ΔE 8 | 양 볼 차이가 크면 한쪽만 그늘졌다는 뜻 |
| `iris_inner` / `iris_outer` | 0.35 / 0.90 | 동공(검정)과 흰자 경계를 뺀 홍채만 |
| `iris_darker_than_skin` | L 10 | 홍채는 피부보다 어둡다 — 아니면 눈꺼풀을 잡은 것 |
| `hair_darker_than_skin` | L 15 | 피부보다 확실히 어두운 픽셀만 머리카락 |

피부 대표색은 **두 볼을 기준으로, 이마는 볼과 비슷할 때만** 픽셀 수 가중평균에 넣습니다.

## ④ 촬영 조건 점검 — `backend/pipeline.py`

두 단계입니다. **막는 선(block)** 을 넘으면 판정하지 않고 재촬영을 안내하고,
**경고 선(warn)** 을 넘으면 판정은 하되 신뢰도를 깎습니다.

```python
if cheek_de > gate["block_cheek_delta_e"]:
    reasons.append("얼굴 좌우 밝기·색 차이가 너무 큽니다 ...")   # 막음
elif cheek_de > gate["warn_cheek_delta_e"]:
    soft.append("얼굴 좌우 색 차이가 있습니다 ...")              # 경고만
```

| 항목 | 경고 | 막음 | 근거 |
|---|---|---|---|
| 양 볼 색차 ΔE | 8 | **15** | 측면광이면 한쪽 볼이 판정을 끌고 감. 다만 실내에서 8~15는 흔해서 막지 않음 |
| 흰 종이 포화 비율 | 15% | **45%** | 반사가 있어도 절반 이상 멀쩡하면 기준색을 뽑을 수 있음 |
| 얼굴 크기 (사진 폭 대비) | 15% | **10%** | 작으면 볼 픽셀이 부족 |
| 화이트밸런스 | — | 실패 시 막음 | 보정 없이는 판정 자체가 의미 없음 |

> 처음엔 ΔE 8 / 포화 10% 를 **무조건 막는 선**으로 뒀는데, 웹캠 9장 중 7장이 막혔습니다.
> 두 단계로 나눈 뒤 6장이 통과하고, 라벨 확실한 4장은 전부 정답입니다.

## ⑤ 웜/쿨 판정 — `backend/diagnosis/season.py` (가장 중요)

```python
def _score_hue(colors, ref):
    """
    색상각 h = atan2(b, a)  (도 단위)
    피부색이 '붉은 쪽'이면 작고 '노란 쪽'이면 크다. 채도(색의 진하기)와 무관해서
    조명이 세거나 홍조가 있어도 덜 흔들린다.
    """
    cfg = ref["warm_cool"]["hue"]
    a, b = float(colors["skin"][1]), float(colors["skin"][2])
    h = float(np.degrees(np.arctan2(b, a)))
    return (h - cfg["threshold"]) / cfg["scale"], {...}
```

**용어 정리**

| 기호 | 뜻 |
|---|---|
| `L` | 밝기 (0 검정 ~ 100 흰색) |
| `a` | 초록(−) ↔ **빨강(+)** — 홍조가 있으면 커짐 |
| `b` | 파랑(−) ↔ **노랑(+)** — 노란 피부면 커짐 |
| `C = √(a²+b²)` | 채도. 색이 얼마나 진한가 |
| `h = atan2(b, a)` | **색상각.** 빨강과 노랑의 비율. 진하기와 무관 |

`b` 만 쓰면 안 되는 이유가 여기 있습니다. 홍조가 심한 쿨톤(`a` 25.6, `b` 23.5)은
`b` 가 크다는 이유로 웜으로 잘못 판정됩니다. `h` 는 **비율**을 보므로 이 사람을 맞힙니다.
실제로 라벨 4장으로 돌려본 결과입니다.

```
방법         경계값    정확도   웜     쿨
hue        43.10    100%   100%  100%
bc        -10.55    100%   100%  100%
b          22.70     50%     0%  100%   ← b만 쓰면 웜을 하나도 못 맞힘
paper_d    10.12     50%     0%  100%
```

| 기준값 | 값 | 근거 |
|---|---|---|
| `threshold` (기준선) | **45.0°** | 라벨 4장 재측정: 웜 47.4°/48.2°, 쿨 43.1°/35.9° → 중간 45.2° |
| `scale` (폭) | **6.0** | 퍼센티지가 급격히 튀지 않게. 팀 안 5°에서 완만하게 조정 |
| `borderline_band` (경계형) | **±1.5°** | 웜 최저와 쿨 최고 간격이 4.3°뿐이라 좁게. 표본 늘면 넓힘 |

판정: `h > 46.5° 웜` / `43.5~46.5° 경계형` / `h < 43.5° 쿨`

**기준선 45°는 잠정값입니다.** 팀 안은 54°인데, 그건 흰 종이 좌표를 손으로 찍은 기준이고
우리는 자동으로 찾아 포화·그림자를 빼므로 값이 평행 이동합니다.
**카메라가 바뀌면 기준선도 이동합니다** — 그래서 재보정 도구를 만들어 뒀습니다.

```

```

## ⑥ 퍼센티지 — 두 단계로

```python
# 1) 웜 대 쿨 비율을 먼저 정한다 (팀 합의 공식)
p_warm = float(1.0 / (1.0 + np.exp(-v_warm)))
p_cool = 1.0 - p_warm

# 2) 이긴 쪽 안에서만 밝기·채도로 두 계절을 나눈다. 진 쪽은 반반으로 둔다.
win_side = 1 if p_warm >= 0.5 else -1
```

곧 `웜 확률 = 1 / (1 + e^-((h − 45) / 6))` 입니다. 기준선에서 정확히 50%, 멀어질수록 벌어집니다.

**진 쪽을 안에서 더 나누지 않는 이유**: 밝기·채도 축(`second_axis`)은 아직 데이터로 검증하지
않았습니다. 진 쪽 안에서 어느 계절인지는 의미가 없는데 그걸 갈라놓으면
`웜 62%인데 1위는 여름 쿨` 같은 모순이 생깁니다. 2,880가지 조합으로 확인해 지금은 모순 0건입니다.

| 기준값 | 값 | 상태 |
|---|---|---|
| `second_axis.lightness.center` | 65.0 | 논문① 뺨 L 평균 64.5 |
| `second_axis.chroma.center` | 22.0 | **검증 안 됨** — 우리 측정 중앙값 근처로 임시 설정 |

> 그래서 화면에서는 **웜/쿨을 주 결과로, 4계절은 참고용으로** 보여주는 게 맞습니다.

## ⑦ 신뢰도 — `backend/diagnosis/confidence.py`

100점에서 깎아 내려갑니다.

```python
score = 100
if q["sharpness"] < 10.0:   score -= 25   # 흐림
if q["brightness"] < 35.0:  score -= 20   # 어두움
if gate_warnings:           score -= min(len(gate_warnings) * 12, 30)
if season_gap < 10:         score -= 20   # 1·2위 차이가 거의 없음
```

| 깎는 이유 | 점수 | 판단 기준 |

| 1·2위 차이 < 10%p | −20 | 경계에 걸림 |

## 확정된 것 / 아직 잠정인 것

| 항목 | 상태 |
|---|---|
| 판정식이 색상각 `h` 라는 것 | **확정** — 홍조 있는 쿨톤을 맞히는 유일한 방법 |
| 화이트밸런스가 필수라는 것 | **확정** — 없으면 같은 사람도 9.7° 흔들림 |
| 절사평균으로 반사광·그림자를 뺀다는 것 | **확정** |
| 기준선 45° | **잠정** — 라벨 4장. 카메라별 재보정 필요 |
| 경계형 폭 ±1.5° | **잠정** — 표본 늘면 넓힘 |
| 4계절 축 (밝기·채도) | **검증 안 됨** — 참고용으로만 표시 |

발표에서 가장 강한 부분은 "기준값을 임의로 정하지 않고, 라벨 데이터로 맞추고 근거를 JSON에
같이 기록했으며, 근거가 없는 항목은 없다고 밝힌다" 는 점입니다.
`data/reference/season_reference.json` 을 열면 모든 숫자 옆에 `_근거` 가 붙어 있습니다.
