## 3. D 값을 어떻게 바꿨는지

| 단계 | 판정식 | 기준 | 문제 |
|---|---|---|---|
| 처음 | 논문① `D = −14.773 + 0.406a + 0.662b` | 0.463 | 연예인 데이터에서 57% 만 맞음 |
| 팀원 | 같은 식 이름, 실제 계산은 `b − C` | −5.5 / −6.0 | 이름과 식이 달라 혼선 |
| 지금 | **색상각 `h = atan2(b, a)` (도)** | **47°** | 홍조(a 큼)에 강함 |

- `b − C` 와 `h` 는 사실상 같은 걸 본다(둘 다 a 대비 b 의 비율). `h` 가 각도라서 해석이 쉽고
  팀 합의안이라 `h` 로 통일했습니다.
- 퍼센티지: `웜 확률 = 1 / (1 + e^-((h − 47) / 6))`
- 판정: `h > 49° 웜` / `45~49° 경계형` / `h < 45° 쿨`

### 기준선이 54° 가 아니라 47° 인 이유
팀 안의 54° 는 **흰 종이 좌표를 손으로 찍어** 측정한 값입니다.
우리 파이프라인은 종이를 자동으로 찾아 포화·그림자 화소를 빼고 평균을 내므로
같은 사진에서도 h 값이 다르게 나옵니다. 라벨이 확실한 웹캠 사진으로 재측정한 값:

| 사진 | 라벨 | 측정 h | 54° 기준 | 47° 기준 |
|---|---|---|---|---|
| 523_05 | 웜 | 51.2° | ✗ 쿨 | ✓ 웜 |
| 328_04 | 웜 | 50.0° | ✗ 쿨 | ✓ 웜 |
| 328_03 | 쿨 | 43.1° | ✓ 쿨 | ✓ 쿨 |
| 190617660 | 쿨 | 33.0° | ✓ 쿨 | ✓ 쿨 |

54° → 4장 중 2장, 47° → 4장 중 4장. 중간값이 46.9° 여서 47° 로 두었습니다.
경계폭도 ±4° → **±2°** 로 좁혔습니다(팀 안의 ±4° 는 웜·쿨 간격이 22° 일 때 값인데
우리 측정은 간격이 7.5° 라 ±4° 면 전부 경계형이 됩니다).

**중요: 기준선 47° 는 라벨 4장으로 잡은 잠정값입니다.** 이번 주 표본이 모이면
`tools/fit_threshold.py` 로 다시 뽑습니다. 촬영 기기가 바뀌면 기준선도 이동합니다.

모든 숫자는 `data/reference/season_reference.json` 한 곳에만 있습니다. 코드는 안 고칩니다.

## 4. 백엔드 ↔ 웹 연결 방법

`app.py` 가 이미 완성돼 있습니다. 프론트(남자 이지수)에게 줄 규격은 이것뿐입니다.

### 요청
```
POST /api/diagnose
Content-Type: multipart/form-data
  image  : 사진 파일 (필수)
  coords : {"x":0.1,"y":0.7,"w":0.2,"h":0.2}   (선택, 화면의 흰 종이 가이드 박스 비율)
```
`coords` 를 안 보내면 백엔드가 흰 종이를 자동으로 찾습니다.

### 성공 응답 (200)
```json
{
  "ok": true,
  "tone": { "verdict": "warm", "label": "웜", "warm_percent": 62.3, "cool_percent": 37.7 },
  "percentages": [ { "key": "spring", "name": "봄 웜", "value": 51.1, "color": "#F7C8B0" }, ... ],
  "best_group": "spring",
  "reliability": 90,
  "reliability_msg": "조명·각도 모두 양호합니다.",
  "message": "봄 웜 톤에 가깝습니다.",
  "warnings": []
}
```

### 재촬영 응답 (400)
```json
{ "code": "retake_required",
  "error": "얼굴 좌우 밝기·색 차이가 큽니다 (ΔE 8.4). 조명을 정면에서 받아주세요." }
```
→ 프론트는 `error` 문자열을 그대로 띄우고 "다시 찍기" 버튼만 보여주면 됩니다.

### 실행
```
python app.py        →  http://127.0.0.1:5000
```
UI 가 아직 미완성이어도 지금 연결해도 됩니다. 규격이 고정돼 있으니 프론트는
`fetch('/api/diagnose', {method:'POST', body: formData})` 만 붙이면 끝입니다.

## 5. 지금 데이터 상태 (솔직한 신호)

웹캠 9장 중 **7장이 `retake_required`** 입니다.
- 흰 종이가 하얗게 날아감 (3장, 깨끗한 화소 13~57%)
- 얼굴 좌우 색 차이 ΔE 8.4~16.3 (4장, 한쪽에서만 조명)

품질 게이트가 제대로 작동하고 있다는 뜻입니다. 이번 주 재촬영은 반드시 아래 조건으로:

1. 흰 A4 를 얼굴 옆 같은 평면에 두기 (조명 직접 받지 않게)
2. 정면 조명, 창·스탠드 한쪽에서 받지 않기
3. 화장 안 한 상태, 얼굴이 화면 가로의 15% 이상
4. 같은 노트북·같은 장소·같은 시간대

같은 사람을 조건 맞춰 2장씩, 웜/쿨 각 5명 이상이면 기준선을 제대로 확정할 수 있습니다.
